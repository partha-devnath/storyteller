## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API mutations | The UI disables buttons from server data; a bypassed UI must still hit the 402 wall server-side (03-02) |
| API response → client state | Billing/limit payloads are the only source for meters/banner/disabled states |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-40 | Tampering | disabled-action bypass | accept | UI disable is UX, not security — server assertLimit (03-02) is the enforcement; 402 handling invalidates billing so the banner reflects truth |
| T-03-41 | Tampering | checkout url redirect | mitigate | useCheckout only navigates to the URL returned by the authenticated POST /billing/checkout (server-authored, HTTPS in prod); never client-built Stripe URLs |
| T-03-42 | Info Disclosure | billing state in UI | accept | Billing payload is member-readable by design (UI-SPEC V2); org-scoped at the API |
| T-03-43 | Spoofing | limit-banner copy | accept | Rendered from server data only; a stale banner self-heals on billing invalidation |
| T-03-SC | Tampering | npm installs | accept | No installs in this plan (shadcn primitives arrived gated in 03-04) |

</threat_model>
