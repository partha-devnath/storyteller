## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client state → UI decisions | Billing/limit data arrives from the API; the UI renders server truth (meters/banner/disabled states) but NEVER trusts it for enforcement |
| browser env → env indicator | import.meta.env values are build-time constants — a staging badge is display-only, no security function |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-30 | Tampering | limit-banner / disabled actions | accept | Display-only by design — real enforcement is the API 402 (03-02); a tampered client state cannot exceed limits (documented, covered by E2E B2 which asserts the banner reflects server data) |
| T-03-31 | Info Disclosure | useBilling data in shell | accept | The billing payload is member-readable by design (UI-SPEC V2); the API already org-scopes it (03-02) |
| T-03-32 | Tampering | onboarding redirect | accept | Session-only skip key; a forged skip only delays a UX redirect, no data access change |
| T-03-33 | Spoofing | env badge | accept | Build-time VITE_APP_ENV; a wrong badge misleads but grants nothing |
| T-03-SC | Tampering | npm installs (shadcn) | accept | Official registry only; vetted in the approved 03-UI-SPEC Registry Safety section (no human checkpoint needed — 02-02 precedent) |

</threat_model>
