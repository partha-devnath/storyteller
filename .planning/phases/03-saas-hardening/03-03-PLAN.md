    Create apps/api/src/services/analytics.ts (named exports only):
    - `export type DailyPoint = { date: string; value: number }` (date = YYYY-MM-DD, UTC).
    - `export function buildDailySeries(rows: { createdAt: Date }[], rangeDays: number): DailyPoint[]` — pure: buckets rows into `rangeDays` daily buckets ending today (UTC), each { date: "YYYY-MM-DD", value: count of rows with createdAt in [dayStart, dayEnd) }. Deterministic, no DB. Today's partial day counts as a bucket.
    - `export function computeTotals(series: DailyPoint[]): number` — pure sum of values.
    - `export async function getAnalytics(orgId: string, rangeDays = 30): Promise<AnalyticsState>` — DB-backed:
      1. projectIds = select project.id where project.orgId = orgId (empty → return zeroed AnalyticsState with empty series, generatedAt now — the UI-SPEC V5c empty state path).
      2. cardsCreated series = buildDailySeries(card rows where projectId inArray(projectIds) and createdAt >= now-30d, 30); proposalsApproved series = buildDailySeries(proposal rows where projectId inArray(projectIds) and status = "approved" and approvedAt >= now-30d, 30) — use approvedAt for the bucket date; commentsPosted series = buildDailySeries(comment rows joined to card on comment.cardId = card.id where card.projectId inArray(projectIds) and comment.createdAt >= now-30d, 30).
      3. activeMembers = distinct count of userId over (proposal.createdBy where approved in range) ∪ (comment.userId where in range) — computed in SQL via union or two counts summed over distinct sets; simplest deterministic: count distinct userIds from proposal rows (approvedAt in range) and comment rows (createdAt in range) within the org's projects.
      4. Return AnalyticsState = { totals: { cardsCreated: sum(cardsCreated series), proposalsApproved: sum(...), commentsPosted: sum(...), activeMembers }, series: { cardsCreated, proposalsApproved, commentsPosted }, generatedAt: new Date().toISOString() }.
    - All date math in UTC; use a helper `dayKey(d: Date): string` = d.toISOString().slice(0,10).

    Tests (bun:test, apps/api/src/__tests__/analytics.test.ts):
    - buildDailySeries: 3 rows with known UTC datetimes → exact { date, value } buckets; empty input → zeroed series of rangeDays buckets; rows outside the window excluded.
    - computeTotals: sums values; empty → 0.
    - getAnalytics is DB-backed: assert it is exported and returns a Promise<AnalyticsState>-shaped object contract via a mocked DB module (dependency-inject the db handle or assert module exports only — keep the suite DB-free and green in CI; real aggregation is proven by E2E A1 in 03-07).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API (analytics) | Org-scoped usage data crosses here; only org members may read, and only their own org's rows |
| client→API (template) | Mutating endpoint creating projects + cards; role-gated and project-limit enforced |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-20 | Info Disclosure | GET /api/orgs/:orgId/analytics | mitigate | requireOrg resolves membership before any query; all aggregations filter projectIds by the authenticated orgId (inArray on the org's project ids) — a second org's rows can never appear |
| T-03-21 | Tampering | template seeding | mitigate | templateId validated as zod enum before seeding (400 on unknown); template content is a compile-time constant, never user-supplied card data |
| T-03-22 | Elevation | template creation | mitigate | requireRole("owner","admin","member") matches the project-create role set; assertLimit(orgId, "projects") blocks template creation over the projects limit |
| T-03-23 | DoS | analytics aggregation | accept | Fixed 30d window + org-scoped subquery; single-node scale; no user-controlled range expansion (enum-locked to 30d) |
| T-03-SC | Tampering | npm installs | accept | No installs in this plan |

</threat_model>
