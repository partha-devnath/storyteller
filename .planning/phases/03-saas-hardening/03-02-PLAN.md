## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API (billing routes) | Any authenticated org member can read billing state; money actions (checkout/downgrade/portal) restricted to owner/admin |
| Stripe→API (webhook) | Untrusted inbound POST; the ONLY auth is the Stripe signature — never trust the body without verification |
| client→API (mutations) | projects/invite/AI/cards endpoints must enforce limits server-side; UI disabling is cosmetic |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Spoofing | POST /api/stripe/webhook | mitigate | `webhooks.constructEvent(rawBody, sig, STRIPE_WEBHOOK_SECRET)` verifies the HMAC signature BEFORE any state change; verification failure → 400 with no DB writes (ASVS L1 webhook verification) |
| T-03-11 | Tampering | plan-limit bypass | mitigate | assertLimit runs server-side at all five mutation sites using PLANS constants (client cannot supply limits); 402 blocks over-limit inserts even if the UI is never opened |
