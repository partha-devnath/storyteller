<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| schemas package → API/E2E consumers | PLANS limits + prices are the enforcement source of truth; any consumer that trusts client-supplied limits breaks enforcement |
| DB → usage service | Count queries must be org-scoped; a missing orgId filter leaks cross-org counts into limit decisions and the billing UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | PLANS config | mitigate | Limits/prices are compile-time constants in @workspace/schemas; the API never accepts limits from the client (validations allow tier only, not limit values) — UI-SPEC "server is source of truth" |
| T-03-02 | Info Disclosure | usage counters | mitigate | Every count query filters by orgId (project.orgId / organizationMember.orgId / project id IN-subquery); no counter accepts a raw user-supplied scope |
| T-03-03 | Tampering | migration SQL | mitigate | drizzle-kit generated file reviewed before apply (additive-only check in Task 3); applied via the standard generate→migrate workflow, never hand-written SQL |
| T-03-04 | Denial of Service | unused | accept | No network surface introduced in this plan (services only) |
| T-03-SC | Tampering | npm installs | accept | No package installs in this plan — the stripe dep arrives gated in 03-02 |

</threat_model>
