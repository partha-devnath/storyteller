<threat_model>

## Trust Boundaries

| Boundary                  | Description                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------- |
| client → API              | Untrusted session headers + request bodies cross here — session check + Zod validation gate |
| API → org data            | Org-id from the URL/body is attacker-controlled — membership lookup is the isolation gate   |
| invite token → membership | A leaked/guessed invite token could grant org access                                        |

## STRIDE Threat Register

| Threat ID | Category               | Component                 | Disposition | Mitigation Plan                                                                                                                                                                        |
| --------- | ---------------------- | ------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-04-01   | Spoofing               | session header            | mitigate    | Every org/project route runs auth.api.getSession first; no route trusts the user-supplied identity (401 on missing session)                                                            |
| T-04-02   | Information disclosure | orgId in query/body/param | mitigate    | requireOrg resolves membership before any data is returned; non-members get 403 with no existence leak; resolveOrgFromProject joins project→org before querying                        |
| T-04-03   | Elevation              | role change / invite      | mitigate    | requireRole("owner","admin") on member management; last-owner guard blocks demotion/removal of the sole owner; invite accept binds the token row to the session user (403 on mismatch) |
| T-04-04   | Spoofing               | invite token              | mitigate    | Tokens are crypto.randomUUID() (128-bit entropy), stored hashed-free (server DB), single-use (nulled on accept), expiry via inviteStatus lifecycle in plan 01-08 E2E coverage          |
| T-04-05   | Tampering              | request bodies            | mitigate    | validateBody applies Zod schemas from plan 01-01; malformed bodies get 400 with field messages, never reach the DB                                                                     |
| T-04-06   | Tampering              | org name/slug collision   | mitigate    | slugify + unique index on org.slug; project (orgId, slug) unique index; DB-level constraint backs API-level validation                                                                 |
| T-04-SC   | Tampering              | npm installs              | accept      | No new npm dependencies in this plan (workspace-internal + existing)                                                                                                                   |

</threat_model>
