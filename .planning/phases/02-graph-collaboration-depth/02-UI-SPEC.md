## Spacing Scale

Multiples of 4 only (Tailwind defaults, as already used in Phase 1):

| Token | Value | Usage                                                             |
| ----- | ----- | ----------------------------------------------------------------- |
| xs    | 4px   | Icon gaps, edge-label padding, inline chip gaps                   |
| sm    | 8px   | Compact element padding (`p-2`), node inner padding, control gaps |
| md    | 16px  | Default element spacing (`gap-4`, `p-4` drawer sections)          |
| lg    | 24px  | Section padding, toolbar-to-canvas gap                            |
| xl    | 32px  | Layout gaps, graph pane padding                                   |
| 2xl   | 48px  | Major section breaks, empty-state vertical rhythm                 |
| 3xl   | 64px  | Page-level spacing (unused in this phase except empty states)     |

Exceptions:

- **Graph node width** = 160px (epic) / 140px (card) — fixed canvas units for layout determinism, not page spacing.
- **React Flow built-in Controls** render library-internal button dimensions (~24px) that may fall off the 8-point grid; acceptable, library-internal, not part of the page grid.
- Interactive controls (toggles, export trigger) keep a minimum h-8 (32px) hit target; no 44px exception needed.

## Color

| Role            | Token                                                                     | Usage                                                                                                                                                                                                      |
| --------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `--background` (light `oklch(1 0 0)` / dark `oklch(0.145 0 0)`)           | Page background, graph canvas background                                                                                                                                                                   |
| Secondary (30%) | `--card`, `--muted`, `--secondary`, `--sidebar`                           | Graph nodes (bg-card), node hover (bg-muted), toolbar container (bg-muted/30), comment bubbles (bg-muted/30)                                                                                               |
| Accent (10%)    | `--primary` (neutral: light `oklch(0.205 0 0)` / dark `oklch(0.922 0 0)`) | **Reserved for:** active view tab, active filter toggle, impact highlight ring, focus rings, links, primary action buttons, selected node border                                                           |
| Destructive     | `--destructive` (existing red)                                            | Destructive actions only. **Phase 2 adds zero destructive actions** (no deletes in graph/comments/export). Existing `close-card` (Phase 1) is the only destructive-ish flow and keeps its current styling. |

**Accent reserved for:** active view-switcher tab, active edge-filter toggle, impact highlight ring (`ring-2 ring-primary`), selected-node border, primary CTA buttons. Never used for decorative fills.

**Selected-node border contract (concrete):** node borders are neutral by default — card nodes keep the existing `--border` token, epic nodes use `border-2 border-foreground/20` (hierarchy level-1 emphasis via border **weight**, not accent color). While impacted (impact mode active), a node's border token switches to `--primary` (`border-primary`) in addition to the `ring-2 ring-primary` highlight. `--primary` as a border color therefore appears **only** on selected/impacted nodes — never as a default node outline.

### New semantic data-color tokens (graph edges) — NOT part of the 60/30/10 budget

Edge type colors are **data encoding** (like the existing `--chart-1..5` slots), not UI accents. Add to `globals.css` `@theme inline` so Tailwind classes (`stroke-edge-dependency`, `text-edge-dependency`) compile:

| Token                     | Value (light)                            | Dark (same hue, +10% L)      | Meaning                      |
| ------------------------- | ---------------------------------------- | ---------------------------- | ---------------------------- |
| `--color-edge-dependency` | `oklch(0.769 0.188 70.08)` (amber-500)   | `oklch(0.828 0.189 84.429)`  | "depends on" / blocked-by    |
| `--color-edge-hierarchy`  | `oklch(0.685 0.169 237.323)` (sky-500)   | `oklch(0.746 0.16 232.661)`  | epic → story containment     |
| `--color-edge-evolution`  | `oklch(0.606 0.25 292.717)` (violet-500) | `oklch(0.702 0.183 293.541)` | closed → replacement lineage |

Node status colors reuse existing conventions: closed card node border `--border` dashed + `opacity-60`; priority chip reuses `priorityClasses` map from `board-card.tsx` verbatim.

## New Dependencies (runtime)

| Package          | Version                 | Purpose                                                                 | Safety Gate                                                                                                                        |
| ---------------- | ----------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `@xyflow/react`  | latest v12.x, pin exact | Graph rendering + pan/zoom/fitView/selection/drag                       | OSS (xyflow), active maintenance, React 19 supported in v12; no network exfil / no dynamic remote imports — view passed 2026-08-02 |
| `@dagrejs/dagre` | latest 1.x, pin exact   | Deterministic layered layout (hierarchy rank: epics top, stories below) | OSS, ~20KB gz, no flags — view passed 2026-08-02                                                                                   |

**Locked graph library decision: `@xyflow/react` (React Flow v12) + `@dagrejs/dagre`.** Rationale:

1. **React 19 compatibility** — v12 declares React 19 peer support (installed React is `^19.2.6`); no wrapper/type hacks needed.
2. **E2E determinism** — nodes and edges are **custom React components** we author, so `data-testid` lands in the DOM we control (see E2E anchors). `dagre` produces **deterministic positions** (no force-simulation jitter), so node/edge coordinates are stable for assertions and screenshots.
3. **Interaction scope** — pan/zoom, fitView, node click, drag, selection, and keyboard a11y are library-provided; hand-rolling these on a custom SVG (`d3-force` path) would add ~200 lines of fragile pan/zoom/hit-testing code for zero benefit at this graph size.
4. **Bundle cost** — `@xyflow/react` ≈ 150KB gz + dagre ≈ 20KB gz. **Lazy-load** the graph view (`React.lazy` route segment) so landing/board bundles are unaffected; the chunk ships only when the user opens Graph.
5. **Scale fit** — boards are tens of nodes; React Flow comfortably handles this. A full graph library remains appropriate at 2–5× future growth; custom SVG is the fallback only if nodes exceed ~500.

Rejected: `d3-force`+custom SVG (hand-rolled interaction, non-deterministic layout), `vis-network` (not React-native, maintenance risk), `react-d3-graph` (thin wrapper, React 19 peer issues).

## Views & Interactions

### V1. Project view switcher (extends `project-board.tsx`)

- Add a **view switcher** above the board area (shadcn `Tabs`): tabs **"Board"** and **"Graph"**.
- Driven by URL query param `?view=board|graph` so deep links work. Default `board`. Graph tab renders `GraphView`.
- `data-testid`: `view-switcher-board`, `view-switcher-graph`. Active tab = `bg-muted font-medium` (existing NavLink pattern), inactive = `text-muted-foreground`.
- **Export menu lives on the Board tab toolbar** (top-right, above kanban), not in the graph — board is the primary export surface.

### V2. Graph view (`graph-view.tsx` + `graph-canvas.tsx` + `graph-node.tsx` + `graph-edge.tsx` + `graph-toolbar.tsx`)

**Data:** `GET /api/projects/:slug/graph` returns `{ nodes: GraphNode[], edges: GraphEdge[] }`.

```
GraphNode = { id, kind: "epic" | "card", title, subtitle?, isClosed?, priority?, epicId? }
GraphEdge = { id, source, target, type: "dependency" | "hierarchy" | "evolution" }
```

Node kinds: epics from `epic` table (incl. `parentEpicId` → hierarchy edges), cards from `card` table (incl. `epicId` membership → hierarchy edge epic→card), `cardRelation` rows → dependency/evolution/hierarchy card edges, closed-card `evolution` relations. Edge direction = schema direction (`sourceCardId → targetCardId`), rendered source→target with an arrow marker.

**Layout:** `@dagrejs/dagre` layered layout, `rankdir: "TB"` — epics rank above their stories; dependency/evolution edges flow through the same DAG. `nodesDraggable: true` (manual adjustments allowed, positions kept in React state only — no persistence). Initial view: `fitView` with padding 32px.

**Node shapes:**

- **Epic node**: width 160px, `rounded-lg border-2 border-foreground/20 bg-card px-3 py-2`, `Layers` lucide icon at 14px + name (`text-sm font-semibold line-clamp-2`), child-count badge `text-xs text-muted-foreground` ("{n} stories").
- **Card node**: width 140px, `rounded-lg border bg-card px-3 py-2 shadow-sm`, title (`text-sm font-semibold line-clamp-2`) + priority chip (reuse `priorityClasses`). Closed cards: `border-dashed opacity-60` + `Lock` icon 12px inline.
- **Node interaction:** click → opens the existing `CardDrawer` for that card (epics: no drawer — show a `Tooltip` "Epic — {name}", click is no-op) + `cursor-pointer`. Hover: `bg-muted` + `Tooltip` showing full title + (for cards) status · priority.
- `data-testid`: `graph-node-{nodeId}` on the node root.

**Edges:** custom edge component rendering a `BaseEdge` path with:

- stroke = type color (`stroke-edge-dependency|hierarchy|evolution`), width 1.5 (idle), arrow marker in same color, rounded path (`border-radius: 5`).
- `data-testid`: `graph-edge-{sourceId}--{targetId}`, `data-edge-type` attr = `dependency|hierarchy|evolution`.
- Edge click → no-op for now (impact works via nodes); hover → stroke-width 2.5.

**Toolbar (top, above canvas; `bg-muted/30 rounded-md px-3 py-2`):**

- **Edge filter toggles** (shadcn `Toggle`, 3): `edge-filter-dependency` "Dependency" (`Link2`), `edge-filter-hierarchy` "Hierarchy" (`GitBranch`), `edge-filter-evolution` "Evolution" (`GitFork`). Active = `bg-primary text-primary-foreground`. Toggling filters the rendered edges AND their connected node counts. Default: all three ON. Filtering is client-side (edges array filter), no refetch.
- **Impact toggle** (`data-testid="impact-toggle"`, `Network` icon, label "Impact", outline → active `bg-primary text-primary-foreground`): arms impact mode. When armed, a helper `Tooltip`/hint under the toolbar reads "Select a card to see its downstream impact."
- **Legend** (inline chips, `text-xs`): amber "Dependency", sky "Hierarchy", violet "Evolution" — uses the three edge color tokens.
- **React Flow `<Controls />`** (zoom in/out/fit) — bottom-left, default look; **no minimap** (too small a graph).

**Impact of X (success criterion 2):**

- When impact mode is armed, clicking a card node triggers impact computation **client-side** from the graph payload: `impact(X)` = X plus every node reachable from X by traversing dependency edges in the **reverse direction** (i.e., all cards that transitively depend on X — "downstream" as rendered). Edges render `source → target` where "source depends on target".
- Rendering while impact active:
  - Impacted nodes + X: full opacity, `ring-2 ring-primary` + `border-primary` (selected-node border contract: border token switches to `--primary` while impacted).
  - All other nodes: `opacity-25`.
  - Impacted edges (dependency edges between impacted nodes, plus hierarchy/evolution edges connecting them): stroke-width **3** (keeps their type color); non-impacted edges `opacity-20`.
  - A banner appears above the canvas: `data-testid="impact-banner"` — "Showing impact of **{card title}**" + `Clear` button (`data-testid="impact-clear"`, ghost, "Clear").
  - Clicking the card **also opens the CardDrawer** (node-click default behavior is preserved; impact highlight and drawer open together).
- Exiting impact mode: `impact-clear` clears state; `impact-toggle` off clears state.

**Empty state** (no nodes in payload): centered stack, `py-24` — heading "No cards yet" (18px/600), body "Generate your first story cards from the Chat tab, then view them here." (14px/400), CTA button "Open Chat" (`data-testid="graph-empty-cta"`, navigates to Chat panel).

**Error state:** banner in canvas area — "Couldn't load the graph." + `Retry` button (`data-testid="graph-retry"`).

**A11y:** React Flow pane keeps default keyboard support (arrow pan, +/- zoom). Node components are rendered as `<div role="button" tabIndex={0} aria-label="Card: {title}">` with Enter/Space click handlers (React Flow handles this for nodes; ensure custom node forwards handlers).

### V3. Polished comments + @mentions (extends `card-drawer.tsx` Details tab)

Replace the raw input + comment list with extracted components:

**`comment-list.tsx`** — threaded list (`parentId` → reply indent `ml-6`):

- Each comment: avatar (initial letter in `bg-muted rounded-full h-6 w-6 text-xs`), author name (`text-xs font-semibold`), relative timestamp (`text-xs text-muted-foreground`, e.g. "2m ago"), body with mention chips rendered.
- Mention chip in body: parse `@Name` tokens from `mentions` ids → render `<span class="rounded bg-primary/10 px-1 text-primary">@Name</span>`; unknown/removed member renders as plain `@handle`.
- Reply affordance: "Reply" ghost link (text-xs) → focuses composer with `parentId` set; "Replying to {name}" mini-header + cancel.
- Empty state: "No comments yet — start the discussion." (12px, muted).
- `data-testid`: `comment-item` per comment (attr `data-comment-id`), `comment-mention` per chip.

**`comment-composer.tsx` + `mention-picker.tsx`:**

- Multi-line `Textarea` (shadcn) `data-testid="comment-input"`, auto-grow up to 4 rows, placeholder: "Add a comment… (type @ to mention someone)".
- Typing `@` opens `mention-picker` (shadcn `Popover` anchored to cursor): list of org members from **existing `useOrgMembers(orgId)`** hook — avatar initial + name, `data-testid="mention-option-{userId}"`. Filter as the user types after `@`. Select → inserts `@Name ` into the textarea and records `userId` in a local mentions set. Backspace over a chip removes it (store as structured segments, not raw text parsing).
- Submit: `Post` button (`data-testid="comment-post"`, primary, sm), disabled when empty/pending. On success: clear composer, invalidate comments query. Payload: `{ body, mentions: string[], parentId? }`.
- Post failure: inline error under composer "Couldn't post your comment. Try again." (12px, destructive).

**Data fix (must-fix from Phase 1):** comments currently load inside `CardDetail.comments` (query key `["card", cardId]`) while `useAddComment` invalidates `["card", cardId, "comments"]` — a key that no query uses, so the list never refreshes. Phase 2 extracts comments into a dedicated query `useCardComments(cardId, projectSlug)` with key `["card", cardId, "comments"]`; detail payload may keep a comment count. SSE `comment.created` invalidates this key.

### V4. SSE live updates (`live-indicator.tsx` + `use-project-events.ts`)

- **Endpoint:** `GET /api/projects/:slug/events` — `EventSource` stream. Events: `comment.created` (`{ cardId, comment }`), `card.created`, `card.updated`, `proposal.ready`. Unknown/other events ignored.
- **Hook `useProjectEvents(projectSlug)`**: opens `new EventSource(...)` on mount when `projectSlug` set; dispatches callbacks; handles `onerror` (EventSource auto-reconnects); exposes `status: "connecting" | "open" | "closed"` and `disconnect()` on unmount. Query invalidation on events: `comment.created` → invalidate `["card", cardId, "comments"]`; `card.created/updated` → invalidate `["project", slug, "cards"]`.
- **`live-indicator`** (top-right of board toolbar, `text-xs` flex row, gap-2): colored dot + label:
  - `connecting` → amber dot, "Connecting…"
  - `open` → green dot (`bg-emerald-500`), "Live"
  - `closed` → muted dot, "Offline — updates paused" + ghost `Retry` button (re-runs connect)
  - `data-testid="live-indicator"` + attr `data-status`.
- **"N new" pill** (in the drawer, under the Comments header): when a `comment.created` event arrives for the open card and the list is not focused, show `data-testid="new-comments-pill"` — "{n} new comment{s}" (12px, `bg-primary/10 text-primary rounded-full px-2 py-1`) with "Jump" action that scrolls the list and clears the count. Non-intrusive — no toast spam, no page reload.

### V5. Export (`export-menu.tsx`, in Board toolbar)

- **Trigger:** `Button` (outline, sm) `data-testid="export-menu"`, `Download` icon + "Export". Disabled (with `Tooltip` "Add cards before exporting") when the board has zero cards.
- **Menu:** shadcn `DropdownMenu` with three items: `export-csv` "Export CSV", `export-json` "Export JSON", `export-markdown` "Export Markdown" (each 14px, `TextIcon`/`Braces`/`FileText` leading icons optional).
- **Mechanism:** `useExport(projectSlug)` fetches `GET /api/projects/:slug/export?format=csv|json|md` → blob → programmatic `<a download>` click. Server sets `Content-Disposition: attachment; filename="{slug}-{YYYY-MM-DD}.{ext}"`. Filename pattern: `{project-slug}-{date}.csv|json|md`.
- **Scope of export:** cards (open + closed, with status/priority/acceptance criteria), epics, and relations — CSV = flat card rows (+ relations flattened as "depends on / hierarchy / evolved from" columns), JSON = full graph payload shape, Markdown = human-readable board doc (epics with nested stories, closed cards flagged).
- Success: no UI needed (browser download). Failure: toast "Export failed. Please try again." (destructive-tinted).

## Interaction & Feedback Rules
