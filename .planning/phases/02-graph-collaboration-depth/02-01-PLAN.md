    Create apps/api/src/services/graph-payload.ts — export ONE pure function buildGraphPayload(epics, cards, relations): { nodes: GraphNode[]; edges: GraphEdge[] } that takes plain row arrays (typeof epic.$inferSelect[], a project-scoped card projection, and cardRelation rows) and returns the payload. NO database access inside the pure function — the route queries, the function maps. Exported types:
    - GraphNode = { id: string; kind: "epic" | "card"; title: string; subtitle: string | null; isClosed: boolean; priority: "low" | "medium" | "high" | "critical" | null; epicId: string | null; childCount: number }
    - GraphEdge = { id: string; source: string; target: string; type: "dependency" | "hierarchy" | "evolution" }
    Mapping rules (deterministic):
    - Epic nodes: one per epic row; kind "epic"; title = epic.name; subtitle null; childCount = count of card rows with that epicId; isClosed false; priority null.
    - Card nodes: one per card row; kind "card"; title = card.title; subtitle null; isClosed = card.isClosed; priority = card.priority; epicId = card.epicId; childCount 0.
    - Hierarchy edges from containment: for each card with epicId, edge { id: `${epic.id}--${card.id}`, source: epic.id, target: card.id, type: "hierarchy" }. For each epic with parentEpicId, edge { id: `${parent.id}--${epic.id}`, source: parent.id, target: epic.id, type: "hierarchy" } (only when the parent epic is in the same project's epic list).
    - Relation edges: one per cardRelation row; id `${sourceCardId}--${targetCardId}`; source/target/type copied verbatim (dependency | hierarchy | evolution). If the same id string already exists from a containment edge, keep only the cardRelation row's edge (containment wins the name; log nothing).
    - Node ids are the DB primary keys (epic.id / card.id) — they are unique across both tables (UUIDs) and become the data-testid contract `graph-node-{id}`.
    All Drizzle queries live in the route (Task 2), following cards.ts' pattern of `where(eq(card.projectId, projectId))` for org scoping — the pure function NEVER receives cross-org data.

    Tests (bun:test, apps/api/src/__tests__/):

    - graph-payload.test.ts: given 1 epic + 3 cards (2 with epicId, 1 without) + 1 dependency relation + 1 evolution relation + 1 epic with parentEpicId, assert exact node kinds/counts and edge list (containment hierarchy edges present, relation edges present with ids `{src}--{tgt}`, parent-epic hierarchy edge present).

## Trust Boundaries

| Boundary                  | Description                                                                                                                                    |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| client→API (graph/export) | Any user's browser requests org-scoped data; unauthenticated + non-member must be rejected                                                     |
| client→API (SSE)          | EventSource connection opens a long-lived stream; only org members may subscribe; cookies only (EventSource cannot send Authorization headers) |
| API mutations→event bus   | Server-internal boundary; events flow from mutation handlers to SSE subscribers of the same projectId                                          |

## STRIDE Threat Register

| Threat ID | Category        | Component                      | Disposition | Mitigation Plan                                                                                                                                                                                                       |
| --------- | --------------- | ------------------------------ | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-02-01   | Spoofing        | GET /api/projects/:slug/events | mitigate    | resolveOrgFromProject middleware (session + org membership) runs before stream creation; non-member gets 403, unauthenticated 401 — same Phase 1 middleware, no bypass path                                           |
| T-02-02   | Info Disclosure | GET /api/projects/:slug/graph  | mitigate    | resolveOrgFromProject + all queries filter by c.var.projectId; the pure builder never sees rows outside the project                                                                                                   |
| T-02-03   | Info Disclosure | GET /api/projects/:slug/export | mitigate    | resolveOrgFromProject; format validated as zod enum (csv\|json\|md) before any serialization; filename built only from project.slug (slugified at creation) + date + whitelisted ext                                  |
| T-02-04   | Tampering       | SSE event payloads             | mitigate    | Events are server-authored JSON from DB rows; event names are a fixed union — client code (02-04) parses EventSource messages, never HTML; comment bodies arrive as JSON text and are rendered as text nodes in 02-04 |
| T-02-05   | DoS             | SSE connections                | accept      | Single-node dev/postgres scale; stream aborts and unsubscribes on disconnect; 25s heartbeat keeps proxies honest. Future hardening: per-IP connection cap (Phase 3)                                                   |
| T-02-06   | Tampering       | comment.created broadcast      | mitigate    | Comment body already zod-validated at POST (max 5000 chars, existing commentSchema); the broadcast re-serializes the same validated values                                                                            |
| T-02-SC   | Tampering       | npm/pip/cargo installs         | accept      | No package installs in this plan — all deps arrive in 02-02, which carries the package legitimacy gate                                                                                                                |

</threat_model>
